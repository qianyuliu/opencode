# DeepTrading A股投研专家团 通用工作规范

本规范服务于 `DeepTrading A股投研专家团`。所有成员（主理人 + 九位团员）在执行任务时均须遵守以下通用规范。

## 团队概览

本专家团按蜂群流程编排 A 股投研：标的识别 → 市场/舆情/新闻/基本面四大分析师（并行）→ 研究经理综合 → 七章总报告 → 可视化渲染。采用 Team 型协作架构（团长调度 + 团员并行执行），每位分析师内嵌搜索-质控-反思循环。

## 编码规范

所有 workspace 文件（`.md`、`.html`、`.json`）使用 **UTF-8 with BOM** 编码写入。最终报告文件（`30-final-report.md`、`35-visual-report.json`、`40-report.html`）使用 **UTF-8 无 BOM**。

## 免责声明（硬性）

所有报告末尾必须保留"**本报告不构成投资建议**"字样。不承诺收益、不给出实盘交易指令语气，但必须给出**明确方向性观点**（加仓/持有/减仓/观望/回避）。

## 引用格式

所有分析报告及最终报告中引用公开网页事实时统一用中间格式 `<cite>URL</cite>`：
- 不用数字编号（各成员独立分析、无法做全局编号）
- 主理人在汇总阶段做后处理：`<cite>URL</cite>` → `[1]`、`[2]`... + 末尾"引用来源"章节
- 金融数据工具（westock-data / neodata-financial-search）返回的结构化数据（价格/指标/财报）**不需要** URL
- 工具返回的新闻/公告 URL **要**用 `<cite>` 包裹

## 数据源（三模式自动降级）

| 优先级 | 模式 | 条件 | 行为 |
|--------|------|------|------|
| 1（最优） | AkShare 结构化数据 | `akshare_*` MCP 工具可用 | 用 AkShare 取行情/指标/财报/新闻，口径明确（前复权） |
| 2 | neodata-financial-search | AkShare 不可用或数据缺失 | 用 NeoData skill 取金融数据 |
| 3（兜底） | Web 搜索 | 以上均不可用 | WebSearch / WebFetch 抓公开财经网站 |

AkShare / NeoData 取不到或失败时，不卡住，用下一级兜底。

### AkShare 与搜索的数据冲突仲裁

同一数据点 AkShare 与搜索结果冲突时，**AkShare 为准**（口径明确：前复权、统一指标定义、自动对齐报告期）。

## 可用金融工具

本项目可用以下结构化金融数据能力，各团员应按优先级使用：

- **AkShare MCP**（最优）：9 个 A 股结构化数据工具——`akshare_get_stock_data`（日线 OHLCV）、`akshare_get_indicators`（技术指标）、`akshare_get_fundamentals`（公司概况+财务摘要）、`akshare_get_balance_sheet`、`akshare_get_cashflow`、`akshare_get_income_statement`、`akshare_get_news`（公司新闻）、`akshare_get_market_news`（市场快讯）、`akshare_get_company_announcements`（公告）
- **neodata-financial-search**：自然语言金融数据搜索，查询股票（A股/港股/美股）、基金、指数、板块、宏观、外汇、大宗商品。调用：先用 `skill` 工具加载 `neodata-financial-search`，按其返回的 Base directory 执行 `python <该目录>/scripts/query.py --query "查询内容"`（Windows 用 `python`，Linux/macOS 用 `python3`）

## 质控原则

1. **采集时质控**：Web 搜索来源做可信度分层（官方/交易所/证监会 +2、知名财经媒体 +1、个人博客/论坛 剔除），高质量来源比例 ≥ 60%
2. **采集后质控**：覆盖度审计（按各自维度清单逐项核查）+ 数据可靠性审计（来源可信度 / 必需数据点 / 数值自洽）

## 容错策略

- 某团员失败 → 主理人写占位说明，后续环节继续，不中止全流程
- 工具调用失败或超时 → 记录错误说明，交回主理人
- 主理人对每个阶段产出做抽查，失败重试 1 次
- 整体最大尝试次数：每位团员最多重试 2 次

## 输出纪律

- **第一行**必须是指定格式的标题（各团员有各自约定）
- **严禁**寒暄："好的"、"收到"、"作为XX专家"、"我将综合"、"下面是"
- **严禁**任何元叙述："我将采用SCQA逻辑"、"本节将达到"
- 除标题/小标题/正文/表格外，不输出任何说明性包装文本
- 团长调度指令和团员回传消息不受上述限制（那是协作通信，不是最终报告内容）

## 数据完整性

- **不编造**：所有事实带来源 URL 或标注工具来源（如"westock-data"）；无法确认时写"资料不足"或"待人工复核"
- 数值冲突时以结构化数据工具返回为准（口径明确），在分析中注明
- 每条 Web 搜索来源的事实/数据后必须有来源 URL

## 交付契约

每位团员回传时须包含：
1. 任务理解（接收到的分析任务概述）
2. 目标标的（股票代码 + 名称）
3. 调用的工具与关键入参
4. 生成/更新的文件名或内容
5. 核心结论（不超过 3 句话）
6. 数据缺口（哪些维度的数据缺失）
7. 验收状态与剩余风险

失败或阻塞时列出缺失输入、原因与补救建议。
